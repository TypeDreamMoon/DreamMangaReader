# DreamMangaReader 番剧单源与混合源设计

## 背景

漫画发现页和小说浏览页已经支持两种来源模式：用户可以选择某个目标源，也可以使用全部已启用源的混合结果；设置中的“显示源选择器”控制页面是强制混合还是允许手动切换。

番剧浏览器目前只有单源状态。它默认使用第一个已启用番剧源，虽然已有番剧源选择弹层和单源按钮，但没有“混合 · 全部源”，也没有响应“显示源选择器”设置。搜索、发现、分页和详情跳转都依赖同一个 `_source` / `_meta`，无法正确承载来自多个源的结果。

## 目标

- 番剧页支持“混合 · 全部源”和单独目标源。
- 与漫画使用相同的“显示源选择器”设置语义。
- 混合模式只使用设置中已启用的番剧源。
- 多源并发加载时快源先显示，单源失败不阻塞其他源。
- 同名番剧合并为一张卡，并显示命中的来源数量。
- 每张卡保留其代表来源，进入详情、加载封面和播放时使用正确源。
- 保留现有番剧搜索、翻译回退、分页、B 站登录和详情页行为。

## 非目标

- 不抽取漫画、小说和番剧共用的通用混合源控制器。
- 不把番剧状态并入漫画 `DiscoveryPage` 的内部加载状态。
- 不增加番剧筛选栏、排行榜板块或详情页跨源切换。
- 不修改番剧源脚本、播放器、下载器或登录协议。
- 不增加新的设置项，不改变现有设置文案。

## 方案选择

采用在 `AnimeBrowser` 内实现独立混合源状态的方案，复用漫画发现页已验证的游标、去重、代际和失败隔离模式。

没有选择以下方案：

- 抽取三类内容共用控制器：长期复用度更高，但会同时重构三个已工作的板块，超出本次范围。
- 将番剧并入漫画发现状态：短期代码可能更少，但番剧详情、B 站登录和播放逻辑会与漫画状态强耦合。

## 状态与组件

### 来源模式

`AnimeBrowserState` 增加混合模式标记，并分别维护：

- 单源模式：一个 `SourceMeta`、一个 `MangaSource` 和全局页码；
- 混合模式：每个已启用番剧源一个独立游标，游标持有 `SourceMeta`、`MangaSource`、当前页、是否有下一页、是否加载中和最近一次是否失败；
- 两种模式共享当前查询、结果列表、加载代际、错误和滚动控制器。

单源来源改为读取 `SourceController.currentFor('anime')`。用户选择具体番剧源时调用 `selectFor('anime', meta)`，沿用现有持久化能力；应用重启后恢复上次单独选择的番剧源。

“混合 · 全部源”只作为当前番剧页面状态，与漫画一致，不增加持久化设置。

### 设置联动

`LibraryStore.showSourcePicker` 的行为与漫画完全一致：

- 关闭时：番剧页强制进入混合模式，隐藏源选择胶囊；
- 开启时：显示源选择胶囊，允许选择“混合 · 全部源”或某个已启用番剧源；
- 设置在页面存活期间发生变化时，`didChangeDependencies` 立即重建来源状态；
- 从强制混合切回可选择模式时，使用 `SourceController` 保存的番剧单源作为默认目标。

源选择弹层继续复用 `showSourcePicker`，传入 `kind: 'anime'`、`includeMixed: true` 和番剧专用混合 ID。

### B 站登录条

B 站登录条只在单源模式且当前源为哔哩哔哩时显示。混合模式隐藏登录条，避免造成全部混合结果都依赖 B 站登录的误解。

用户需要登录、查看追番或退出时，可以先在源选择器中切换到哔哩哔哩。现有登录成功刷新和退出刷新行为保持不变。

## 结果模型与展示

番剧结果不再只保存 `Manga`，而是保存：

- 番剧数据；
- 代表来源 `SourceMeta`；
- 搜索相关度或稳定插入顺序所需的排序信息。

混合模式按归一化标题去重。首次出现的标题建立卡片，并保留最先返回的来源作为代表来源；之后其他源返回同名番剧时不重复建卡，只把源 ID 累加到该标题的来源集合。

命中两个及以上来源时，封面使用现有 `MangaCover.sourceCount` 显示“N 源”角标。单源模式不显示多源角标。

卡片的封面请求头、Hero 标识和详情跳转都使用该结果保存的代表来源，不读取页面当前的全局 `_meta`。这样即使多源结果异步交错，每张卡仍会进入正确的 `AnimeDetailPage(meta, anime)`。

本次不增加详情页跨源选择。用户需要指定来源时，可回到列表选择目标单源后重新搜索或浏览。

## 加载与分页

### 单源

单源继续按当前查询调用 `getSearch`，空查询调用 `getDiscovery`。返回顺序保持源自身顺序，分页规则保持现状。

### 混合源

重建混合模式时，为每个已启用的 `kind == 'anime'` 源创建游标。加载首页或滚动接近底部时，对所有尚有下一页且未在加载的游标发起请求：

- 每个源独立递增页码；
- 快源结果立即并入列表，不等待慢源；
- 某源返回空页或 `hasNext == false` 后停止该源；
- 某源抛错后停止该源本轮后续分页，其他源继续；
- 混合总体加载状态为任一游标正在加载；
- 混合总体下一页状态为任一游标仍有下一页。

浏览模式保持异步到达顺序。搜索模式沿用漫画搜索相关度规则：精确同名优先，同分结果保持稳定到达顺序，避免先返回的模糊结果长期占据首位。

## 搜索与翻译回退

顶栏仍通过 `AnimeBrowserState.runSearch` 传入查询。每次新查询会：

1. 保存原查询并清空翻译候选；
2. 递增加载代际；
3. 清空结果、错误、去重表和所有游标页码；
4. 按当前单源或混合模式重新加载。

单源翻译回退保持现有行为。混合源必须等待所有游标结束且结果仍为空，才为原查询生成一次翻译候选队列；不能由每个源独立触发翻译，避免重复请求和重复搜索。

如果有任何结果、存在全源错误或仍有游标加载中，不启动翻译回退。尝试新译名时重置所有混合游标，再由全部已启用番剧源搜索该译名。

## 代际与资源生命周期

每次切换来源模式、选择目标源、重新搜索或执行重试都会递增加载代际。异步请求完成后必须同时验证组件仍挂载且请求代际仍为当前值；不满足时丢弃结果，不能修改列表、页码或错误状态。

重建来源前统一销毁原单源实例和所有混合游标中的源实例。页面销毁时再次完成同一清理，并移除 `SourceController` 监听。

来源设置发生变化时重新计算已启用番剧源：

- 混合模式只重建仍启用的番剧源；
- 当前单源被禁用时回退到 `SourceController.currentFor('anime')` 的有效源，或第一个已启用番剧源；
- 没有可用番剧源时进入现有无源空态，不发起加载。

## 错误与空状态

- 单源失败：显示现有错误内容和重试按钮。
- 混合模式单个源失败：记录该源错误并停止该游标，不覆盖已有结果，也不影响其他游标。
- 所有混合源都失败且没有结果：显示错误状态和重试按钮。
- 至少一个源成功完成但所有成功结果为空：显示正常“没有内容”空状态。
- 已经有部分结果时其他源失败：保留结果，底部停止失败源，不用全屏错误替换内容。
- 重试会递增加载代际、复位当前模式全部游标并重新请求。

## 本地化与界面一致性

复用现有番剧源选择标题和通用混合源文案：

- `srcpick_titleAnime`
- `srcpick_mixedGlyph`
- `srcpick_mixedAllSources`
- `srcpick_mixedSubtitle`
- `disc_mixedAllSources`

不新增仅用于重复表达的文案。源选择胶囊、弹层、封面角标、网格尺寸和列表排版继续使用现有公共组件，与漫画保持一致。

## 测试与验收

新增聚焦 Widget/状态测试，使用可控假番剧源覆盖：

- 设置关闭源选择器时强制混合并隐藏胶囊；
- 设置开启时显示胶囊，并可在混合源和单源之间切换；
- 单源选择通过 `SourceController` 持久状态更新；
- 混合首页并发请求全部已启用番剧源；
- 禁用番剧源不参与混合请求；
- 快源结果先显示，慢源完成后正确追加；
- 同名番剧只显示一次并累加来源数量；
- 点击混合结果时传入该卡保存的正确来源；
- 单源失败不影响其他源，全部失败显示错误，成功空页显示空状态；
- 混合源各自独立翻页；
- 切换模式或查询后旧请求返回不污染新列表；
- 混合翻译回退只在全部源完成且零结果时触发一次；
- B 站登录条仅在单选 B 站时显示；
- 页面销毁后在途请求不更新状态。

验证范围包括新增测试、现有番剧详情/播放/历史相关回归、聚焦静态分析和 `git diff --check`。本阶段不运行 Windows/Android 完整构建、打包或真机测试。
