# DreamMangaReader 统一后台下载系统设计

日期：2026-08-06
状态：已确认，等待实施计划
目标平台：Android、Windows

## 1. 背景

当前软件中的下载能力彼此独立：

- 漫画由 Flutter 内的 `DownloadStore` 按章节逐页下载。
- 小说由 Flutter 内的 `NovelDownloadStore` 下载章节正文和插图。
- 番剧播放器分支提供 HLS 播放缓存，但没有正式离线下载任务。
- Android 应用更新分支使用前台服务、系统通知和断点续传下载 APK。

漫画和小说队列依赖 Flutter 进程。应用被系统挂起或终止后，任务不能像应用更新一样继续。不同类型也没有统一的暂停、恢复、网络、存储和错误模型。

本设计将这些能力收敛为一个接近主流视频应用使用体验的统一下载系统。它复用后台更新的生命周期、通知和传输机制，但保留漫画、小说、番剧和应用更新各自的解析、校验与落盘规则。

## 2. 目标

系统必须做到：

1. 统一管理番剧、漫画、小说和应用更新下载任务。
2. Android 在锁屏、切换应用或从最近任务划掉界面后继续下载，并显示系统通知。
3. Windows 关闭主窗口后可留在系统托盘继续下载，也可由用户设置为直接退出。
4. 支持暂停、继续、取消、失败重试、批量操作、队列排序和应用重启恢复。
5. 支持仅 Wi-Fi、移动网络确认、禁止漫游、并发限制、存储空间限制和目录迁移。
6. 番剧使用应用内部 HLS 分片离线播放，不导出 MP4。
7. 正式离线内容与临时播放缓存严格分开。
8. 不在普通任务文件、日志、备份或云同步中泄露 Token、Cookie、HLS 密钥和签名地址。

## 3. 非目标与系统边界

- 不绕过 Widevine、FairPlay 等商业 DRM。仅提供 DRM 流时显示“不支持离线下载”。
- 不保证在 Android 系统设置中被“强行停止”后继续运行；这是系统级限制。
- 不在后台自动处理验证码、Cloudflare 人机验证或必须交互的 WebView 登录。
- 不导出番剧 MP4，也不把离线媒体内容上传到云同步。
- 不把本地导入的 TXT、EPUB 当作网络下载任务。

第三方源如果返回短期签名 URL，后台服务会在有效期内继续下载。地址过期且通用重试无法恢复时，任务进入“等待源刷新”。Flutter 下次运行后调用 QuickJS 源重新解析剩余资源并续传。已有正确文件不会重下。

## 4. 总体架构

### 4.1 Dart 统一协调层

`DownloadCoordinator` 是任务状态的唯一业务入口，负责：

- 加载和持久化任务；
- 队列、优先级和并发调度；
- 网络、电量和存储策略；
- 作品任务与子项任务的汇总进度；
- 调用内容执行器和平台后台执行器；
- 向下载中心、通知桥和托盘桥发布状态事件。

现有下载能力迁移为四种执行器：

- `MangaDownloadExecutor`
- `NovelDownloadExecutor`
- `AnimeDownloadExecutor`
- `AppUpdateExecutor`

所有执行器遵守同一任务协议，但内容解析、资源清单和完成校验相互隔离。应用更新具有独立优先级，不能被大量内容任务长期阻塞。

### 4.2 持久化

项目不直接引入依赖移动端 `sqflite` 的实现。此前 Windows 缺少对应实现会导致运行时失败，因此使用跨平台文件日志：

- 一个小型总索引保存任务顺序、作品摘要和当前状态；
- 每个任务有独立、带版本号的 `manifest.json`；
- 写入采用临时文件加原子替换；
- 大量图片或 HLS 分片的完成状态优先从实际文件及校验信息恢复，避免频繁重写巨大 JSON；
- `.download` 只代表未完成文件，校验成功后才原子改为正式名称。

### 4.3 Android 后台层

现有 `UpdateDownloadService` 的通用部分抽取为内容无关的前台下载服务。Flutter 将已经解析好的资源清单交给服务，服务负责：

- HTTP Range 续传；
- 请求头和重定向处理；
- 文件级校验与原子落盘；
- 合并进度通知；
- 暂停、继续、取消和恢复；
- 网络策略和磁盘错误反馈。

认证数据通过 Android 安全存储按凭据引用读取，不写入普通任务 JSON。源需要重新执行脚本或 WebView 交互时，服务返回明确的等待状态，而不是无限重试。

### 4.4 Windows 后台层

Windows 保持 Dart 下载执行器运行，并增加系统托盘生命周期：

- 默认关闭主窗口时隐藏到托盘并继续下载；
- 设置可切换为直接退出；
- 直接退出前持久化队列，下次启动恢复；
- 托盘菜单提供显示主窗口、暂停全部、继续全部和退出；
- 只有明确选择退出才终止后台进程。

## 5. 任务模型

任务分为三层：

1. 作品任务：一部番剧、漫画或小说。
2. 子项任务：一集、一章或一话。
3. 资源项：视频分片、图片、正文资源、字幕、密钥或安装包分片。

下载中心默认显示前两层，不向用户暴露几百个底层资源项。

主要状态流为：

```text
等待解析 -> 排队 -> 下载中 -> 校验 -> 已完成
```

可恢复的等待状态包括：

- 用户暂停；
- 等待 Wi-Fi；
- 等待可用存储；
- 等待重新登录；
- 等待源刷新；
- 等待系统允许；
- 等待外部存储重新挂载。

错误记录必须包含稳定错误码、用户可读说明、失败资源、HTTP 状态和重试次数。日志必须清理 URL 查询参数和认证信息。

## 6. 调度与恢复

- 默认同时处理 2 个作品，设置允许选择 1 至 3 个。
- 每个域名单独限制资源并发，避免大量图片触发源站封禁。
- 前台播放和阅读请求优先于后台下载。
- 网络超时按有上限的退避策略重试。
- `401/403` 根据源能力转为重新登录或源刷新。
- `404` 在重新解析后仍不存在才判定永久失败。
- 空间不足立即暂停相关任务，不循环创建临时文件。
- 启动 APP、恢复服务或重新挂载存储时，对照清单与实际文件重建状态。
- 图片和 HLS 分片按文件粒度恢复；损坏资源单独重下。
- 删除任务时提供“只移出队列”和“同时删除文件”。

## 7. 网络与电量策略

- 默认仅 Wi-Fi 自动下载。
- 移动网络提供“仅本次允许”和“始终允许”。
- 漫游网络默认禁止。
- Wi-Fi 中断时暂停，恢复后自动继续。
- 低电量暂停为可选设置，默认关闭。
- Android 前台服务通知存在时，从最近任务划掉界面不取消下载。
- 系统强行停止后，最迟在用户重新打开 APP 时恢复任务。

## 8. 存储策略

- Windows 默认应用数据目录，可选择其他目录。
- Android 可选择内部存储或系统授权的外部目录。
- 默认预留至少 2 GB 可用空间。
- 下载前尽力估算体积；无法准确估算时持续检查剩余空间。
- 正式离线内容不受普通“清理缓存”影响。
- 切换目录默认只影响新任务，同时提供主动迁移已有内容。
- 迁移采用复制、校验、切换索引、删除旧文件的顺序；失败时保持旧位置有效。
- 外部目录消失时暂停任务，不自动改写到其他目录。

## 9. 番剧离线下载

支持常见 HLS 点播能力：

- Master Playlist 和多清晰度；
- MPEG-TS 与 fMP4；
- AES-128 HLS 密钥；
- `BYTERANGE` 和初始化分片；
- HTTP 重定向；
- WebVTT 字幕和源明确提供的音轨；
- 本地 HLS 清单重写与完全离线播放。

清晰度采用“全局默认 + 单次覆盖”：

- 智能；
- 1080P；
- 720P；
- 最低流量。

任务开始后固定画质，不在同一集内混用画质。重新选择其他画质时删除后重下。播放缓存可以在资源校验一致时转入正式下载；播放缓存可自动淘汰，正式下载只能由用户主动删除。

## 10. 漫画离线下载

- 按章节保存原始图片格式和稳定顺序。
- 兼容 HTTP、本地文件及受支持的 Base64 图片。
- 单页失败只重试该页。
- 临时地址刷新后保留已完成页面。
- 完整章节校验前不标记为可离线阅读。
- 长图集继续使用现有延续分页能力。

## 11. 小说离线下载

- 保存安全清理后的章节正文、插图和目录信息。
- 支持单章、选择章节和整本加入队列。
- 源目录更新后允许只下载新增章节。
- 章节正文成功但插图不完整时保持未完成状态，并允许只重试资源。
- 本地 TXT、EPUB 导入流程保持独立。

## 12. 下载中心

下载中心使用两层筛选：

```text
下载中 / 已完成
番剧 / 漫画 / 小说
```

作品卡片显示封面、当前集或章节、总进度、实时速度、预计剩余时间、占用空间和暂停操作。展开后管理单集或单章。长按进入多选，支持批量暂停、继续、重试、删除和调整优先级。

已完成内容按作品聚合，进入后查看离线子项和实际占用空间。错误必须显示明确原因和可执行操作，而不是只有“下载失败”。

## 13. 通知与托盘

Android 使用一条聚合前台通知显示总进度和当前作品，提供暂停全部、继续和取消当前操作。完成和失败使用摘要通知，不为每个图片或分片创建通知。

Windows 托盘显示活动任务数量，提供显示窗口、暂停全部、继续全部和退出。选择直接退出且仍有任务时，提示任务已保存、下次启动继续，但不阻止退出。

## 14. 设置

设置页增加“下载”分区：

- 默认番剧画质；
- Wi-Fi、移动网络和漫游策略；
- 作品并发数量；
- 下载目录、空间占用、预留空间和迁移；
- 下载进度、完成和失败通知；
- Windows 关闭行为；
- 收藏作品更新后自动下载，默认关闭；
- 低电量暂停，默认关闭；
- 视频播放缓存容量和清理。

## 15. 安全

- 所有目标路径必须解析后仍位于授权下载根目录内。
- 拒绝路径穿越、绝对路径注入、危险文件名和超出清单限制的资源数。
- Token、Cookie、HLS 密钥和签名 URL 不进入日志、普通任务文件、备份或云同步。
- 敏感数据使用平台安全存储，并通过凭据引用关联任务。
- 删除作品后清理不再被任何任务引用的密钥和临时认证数据。
- 云同步只同步阅读进度和作品标识，不同步离线文件。

## 16. 兼容与迁移

现有漫画和小说下载记录升级为统一索引时：

1. 保留旧索引和原文件。
2. 扫描已有完整章节并建立新的完成记录。
3. 原子写入新索引后才标记迁移成功。
4. 迁移失败时继续使用旧记录，不删除用户内容。

迁移不要求移动文件或重新下载。旧数据格式至少保留一个发布周期的只读回退能力。

## 17. 验收与测试

Dart 层必须覆盖：

- 队列、优先级、并发、网络策略和空间限制；
- 原子持久化、崩溃恢复和旧数据迁移；
- 暂停原因、错误分类和重试上限；
- 下载中心的批量操作和筛选。

内容执行器必须覆盖：

- 漫画缺页、乱序、Base64、地址刷新和整章恢复；
- 小说正文、插图、整本、新增章节和删除恢复；
- 番剧 TS、fMP4、AES-128、BYTERANGE、字幕、断网续传和本地播放。

平台验收必须覆盖：

- Android 锁屏、划掉最近任务、网络切换、低电量、重启和通知操作；
- Windows 托盘、直接退出、目录迁移和重启恢复；
- 路径穿越、恶意清单、认证泄漏、损坏文件和存储拔出。

静态测试不能替代真实平台验证。Android 前台服务生命周期和通知必须使用真机检查；Windows 托盘与退出行为必须在桌面运行验证。

## 18. 实施顺序与分支依赖

按以下阶段实施，每阶段均可独立测试：

1. 统一任务模型、文件持久化和调度策略。
2. 迁移现有漫画与小说下载。
3. 下载中心和设置页。
4. Android 通用前台下载服务，基于 APP PR #7 的后台更新能力。
5. Windows 托盘和关闭行为。
6. 番剧 HLS 离线执行器，复用 APP PR #8 的解析、缓存和恢复能力。
7. 私有源凭据引用和认证恢复，兼容 APP PR #9。
8. 平台集成、旧数据迁移和真实设备验收。

当前统一下载分支基于作者 `v1.6.0`，并直接合入 APP PR #7、#8、#9 的原分支提交作为后续平台集成基线。这里不复制三组实现；作者以后使用普通 Merge 合并这些 PR 时，Git 可按相同提交身份识别已合并历史。若作者使用 Squash Merge 导致提交身份变化，则同步作者 `main` 时按内容消除重复并处理实际新增差异。
