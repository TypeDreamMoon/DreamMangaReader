# DreamMangaReader 页面转场隔离设计

## 背景

当前主题把 `Scaffold` 背景设为透明，以透出统一的 `AppBackground`。与此同时，普通 `MaterialPageRoute` 使用 `FadeUpwardsPageTransitionsBuilder`，`appRoute` 也会让整个页面淡入淡出。

Flutter 在路由动画期间会同时绘制前后两个页面。透明页面整体淡化时，背景先露出下层页面，而当前页面的文字和控件仍未消失，因此用户会短暂看到两套页面元素。这是转场结构与透明背景不兼容，不是页面销毁或异步状态更新延迟。

## 目标

- 页面切换期间不同时显示前后两个页面的文字、图片或控件。
- 保留统一自定义背景、详情封面色融合和页面状态。
- 参考 Apple 的页面层级与动效节奏，但保持 Android、Windows 和桌面返回操作一致可用。
- 关闭界面动画后直接切换，不保留过渡延迟。

## 非目标

- 不重做页面布局、导航结构或背景设置。
- 不增加 iOS 边缘返回手势。
- 不修改弹窗、底部面板、阅读器翻页和播放器内部动画。
- 不为不同平台维护多套业务页面。

## 转场分类

### 主栏目

书库、发现、下载和设置继续由 `IndexedStack` 保存已经访问页面的状态和滚动位置。

切换栏目时旧栏目立即进入 `Offstage`，只有新栏目参与入场。全局背景保持不动，新栏目内容使用约 120ms 的轻微淡入；现有标题栏和内容区域的方向入场可以保留，但不得驱动旧栏目。

### 层级路由

进入详情、浏览、账户和日志等完整页面时，采用 Apple 风格的水平层级转场：

- 新页面在约 240ms 内从右侧少量推入到原位；
- 下层页面只做很轻的左移，不改变透明度；
- 返回时方向相反，当前页面向右退出；
- 动画使用 ease-out 类型曲线，避免长时间拖尾。

每个活动路由必须拥有独立的全屏背景隔离层。隔离层复用当前主题、自定义背景图、模糊、遮罩和详情色融合，但不参与内容透明度动画。进入和返回期间，隔离层始终遮住下层页面元素；只有当前路由内容执行位移或淡入。

### 弹层

Dialog、BottomSheet、菜单和阅读器内部控件继续使用现有动画，不套用完整页面的水平路由转场。

## 实现边界

- 提取可复用的背景绘制层，使应用根背景和路由隔离背景使用同一实现，避免复制设置逻辑。
- `appRoute` 和主题中的普通 `MaterialPageRoute` 使用同一页面转场构建器，消除两套行为差异。
- 路由背景与内容动画分层：背景保持完整，动画只作用于内容。
- `LibraryStore.animationsEnabled == false` 时，路由和主栏目都使用零时长直接切换。
- 不改变路由栈、页面生命周期、Hero 标识或 Store 所有权。

## 异常与兼容

- 背景图加载失败时继续使用主题底色兜底，转场期间仍不能透出旧页面元素。
- 快速连续切换主栏目时，以最后一次选择为准，旧动画从当前值重新开始，不重新创建页面状态。
- Android 系统返回、Windows 返回操作和代码中的 `Navigator.pop` 使用同一反向转场。
- Hero 动画若存在，仍位于隔离背景之上；非 Hero 元素不得穿透背景层。

## 测试与验收

- Widget 测试在路由动画中间帧验证背景隔离层存在；前后页面可以像 Apple 水平推入一样分处屏幕两侧，但新页面覆盖的像素区域不得透出旧页面元素。
- Widget 测试验证 push 和 pop 使用相反方向，动画结束后路由栈内容正确。
- 主栏目测试验证切换中旧栏目为 `Offstage`，新栏目保留状态，并覆盖关闭动画的直接切换。
- 运行相关导航、主题和应用启动测试，以及聚焦静态分析和 `git diff --check`。
- 本阶段不运行 Windows/Android 完整构建、打包或真机测试。

## 延后验证

- Windows 实际窗口中的鼠标返回与连续导航观感。
- Android 真机返回键、低刷新率设备和自定义背景图下的转场流畅度。
- Hero 封面动画与详情色融合的实际视觉检查。
