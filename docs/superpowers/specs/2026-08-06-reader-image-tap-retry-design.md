# DreamMangaReader 漫画单图点击重试设计

## 背景

漫画阅读器的网络页使用 `CachedNetworkImage`。请求或解码失败后，`errorWidget` 只返回静态破图占位；组件没有重试状态，也不会主动更换图片键，因此用户通常只能退出阅读器再重新进入，让整页重新构建。

分页、双页和长条模式最终都通过 `ReaderPage._image` 创建图片，适合在这一共同边界增加单图重试，不需要刷新章节或重建阅读器。

## 目标

- 网络漫画图片加载失败后，单击失败占位即可重新加载这一张图片。
- 重试只影响当前 URL，不重建章节中已经成功的图片。
- 分页、双页、竖翻和长条模式行为一致。
- 保留图片请求头、缓存管理器、加载进度和现有布局尺寸。
- 成功图片原有的翻页、控制栏、缩放和双击手势不受影响。

## 非目标

- 不增加整章刷新按钮或自动循环重试。
- 不修改漫画源脚本、图片解密和网络代理逻辑。
- 不对 Base64 内联图片或本地下载文件执行网络重试。
- 不改变预加载数量、阅读进度或下载记录。

## 组件设计

新增一个专门负责网络阅读页的 StatefulWidget。它接收 URL、请求头、`BoxFit`、宽高、长条占位尺寸和缓存管理器，并在内部构建 `CachedNetworkImage`。

组件维护：

- 当前重试序号，用作 `CachedNetworkImage` 的稳定 attempt key；
- 是否正在清理并重试，用于阻止连续点击产生并发请求。

正常加载沿用现有百分比占位和 120ms 图片淡入。成功后只显示图片，不附加新的点击手势。

失败时显示原有破图图标和现有本地化“重试”文案，整个失败区域可以单击。点击后：

1. 立即进入重试中状态，忽略后续点击；
2. 驱逐该 URL 对应的 Flutter `ImageCache` 条目；
3. 从 `appImageCache` 删除该 URL 的磁盘缓存，避免损坏缓存反复解码失败；
4. 增加 attempt key 并重新构建 `CachedNetworkImage`；
5. 使用完全相同的 URL、headers、fit 和尺寸重新请求。

缓存清理失败不阻止重试。组件仍增加 attempt key 并重新请求；清理异常不弹出全局错误，以免弱网下连续打断阅读。

## 手势边界

只有 `errorWidget` 返回的失败区域拥有单击手势。成功图片和加载占位不添加 `GestureDetector`，因此外层 `_ZoomableView`、页面点击分区和滚动手势保持原行为。

长条模式中点击失败项不会改变列表位置或其他项的 Key。分页和双页模式中只重建对应图片子树，不切页、不复位阅读进度。

## 异常与兼容

- HTTP 失败、连接中断和图片解码失败使用同一点击重试入口。
- Base64 与本地文件失败继续显示静态破图占位；重复读取相同损坏内容没有恢复价值。
- 重试过程中页面被销毁时，异步缓存清理结束后不得调用 `setState`。
- 同一 URL 在不同阅读位置出现时，本次点击会清除该 URL 的共享缓存；其他已显示实例不主动重建，之后需要加载时会获取新缓存。

## 测试与验收

- Widget 测试让第一次图片请求失败，确认出现可点击失败占位。
- 单击后确认只触发一次缓存驱逐并增加 attempt key，第二次请求成功后失败占位消失。
- 连续点击失败占位时确认不会产生并发重复重试。
- 验证 URL、headers、fit、宽高和长条模式占位参数在重试前后保持不变。
- 验证 Base64 和本地文件分支不获得网络重试手势。
- 运行相关阅读器、Base64 页面、图片数据和缓存测试，以及聚焦静态分析与 `git diff --check`。
- 本阶段不运行 Windows/Android 完整构建、打包或真机测试。

## 延后验证

- Android 真机弱网、代理切换和连续断网恢复。
- Windows 实际鼠标点击、双页与缩放状态下的手势体验。
- 真实漫画源的防盗链请求头、损坏缓存和长条章节联调。
